## 🏗️ Arkitektur

### Supabase-tabeller og ansvarsfordeling
| Tabell | Rolle | Viktige kolonner |
|---|---|---|
| `strategies` | Read-only template-katalog | `id`, `is_active` (IKKE `status`, IKKE `user_id`) |
| `trading_sessions` | Aktiv brukerinstans | `id`, `user_id`, `status`, `strategy_id`, `strategy_config` |
| `user_profiles` | Brukerprofil | `id`, `user_id`, `subscription_tier`, `stripe_customer_id` (IKKE `stripe_subscription_id`) |
| `subscriptions` | Stripe-abonnement | `id`, `user_id`, `stripe_subscription_id`, `stripe_customer_id`, `plan_type` |
| `positions` | Åpne posisjoner | `id`, `user_id`, `portfolio_id`, `symbol`, `quantity` (IKKE `session_id`) |
| `marketplace_subscriptions` | Marketplace-abonnenter | `id`, `subscriber_id`, `listing_id`, `user_strategy_id` (nullable, ingen FK) |

### Kritiske invarianter
1. `strategies` = template → aldri skriv brukerinstanser hit
2. `trading_sessions` = runtime instance → alltid opprette brukerinstanser her
3. `user_profiles.stripe_subscription_id` finnes IKKE → bruk `subscriptions.user_id` som bro
4. `positions.session_id` finnes IKKE → bruk `user_id` i stedet
5. `strategies.is_active` (boolean) → IKKE `.eq("status", "active")`
6. `trading_sessions.status` (string) → `.eq("status", "active")` er korrekt
7. `risk_config` leses fra `session.strategy_config.risk_config` (IKKE fra separat kolonne)
8. `portfolios` har IKKE `symbol` → bruk `positions` (har `symbol`)
9. `trades` har IKKE `symbol` → bruk `trading_pair`

## 🚨 Kjente feilmønstre + hurtigfix

### Mønster 1: `Argument of type '"bad_col"' is not assignable`
**Rotårsak**: `.eq("bad_col", ...)` på tabell der kolonnen ikke finnes i `supabase-generated.ts`
**Hurtigfix**:
```bash
node scripts/guard-supabase-columns.mjs --fix
git add -A && git commit -m "fix(supabase): align .eq calls" && git push
```

### Mønster 2: `user_profiles.stripe_subscription_id`
**Rotårsak**: `user_profiles` har ikke `stripe_subscription_id`; den finnes i `subscriptions`
**Fix-mønster**:
```ts
// Hent user_id via subscriptions
const {  sub } = await supabase
  .from("subscriptions")
  .select("user_id")
  .eq("stripe_subscription_id", subscriptionId)
  .single();
if (sub?.user_id) {
  await supabase.from("user_profiles").update({...}).eq("id", sub.user_id);
}
```

### Mønster 3: `positions.session_id`
**Rotårsak**: `positions` har ikke `session_id`; bruk `user_id`
**Fix**:
```ts
.eq("user_id", user.id) // IKKE .eq("session_id", session_id)
```

### Mønster 4: `strategies.status`
**Rotårsak**: `strategies` bruker `is_active` (boolean), ikke `status` (string)
**Fix**:
```ts
.eq("is_active", true) // IKKE .eq("status", "active")
```

### Mønster 5: `session.risk_config`
**Rotårsak**: Ingen separat `risk_config`-kolonne; leses fra `strategy_config`
**Fix**:
```ts
const stratCfg = (session.strategy_config as Record<string, unknown>) ?? {};
const riskConfig = (stratCfg.risk_config as RiskConfig) || DEFAULTS;
```

## 🚨 CI/CD Gate-regler (ALLTID følges av KIMI og agenter)

1. **`tsc --noEmit` MÅ returnere exit 0 FØR `git push`** — ingen unntak
2. **`|| true` er FORBUDT** på TypeScript-sjekk-steg i CI
3. **Vercel bygger parallelt med Actions** — Ignored Build Step er eneste gate
4. **GitHub Branch Protection**: krev `typecheck / tsc --noEmit` grønn på main
5. **KIMI**: Alltid `npx tsc --noEmit && echo TSC_OK` som siste steg før push
6. **Blokkerende workflow**: `.github/workflows/typecheck.yml` — ny fil, ingen `|| true`
7. **Husky**: `.husky/pre-commit` MÅ inneholde full `tsc --noEmit`, ikke bare grep-guard
8. **Bot-commits** (auto-fix): legg `[skip ci]` i commit-message for å unngå loop
9. **Gjenbrukbar KIMI-prompt**: `scripts/kimi-ci-gate-fix.md`
