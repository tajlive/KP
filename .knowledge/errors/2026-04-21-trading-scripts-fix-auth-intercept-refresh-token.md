# [Trading,Scripts] fix(auth): intercept refresh_token at fetch level to stop gotrue-js cascade

The getSession/getUser wrappers alone couldn't stop gotrue-js internal
retry storms because signOut() triggers _removeSession() -> subscribers
-> _refreshAccessToken() bypassing method wrappers.

Changes:
- global.fetch wrapper in createBrowserClient intercepts ALL refresh_token
  requests at the network layer, blocking them after first 400
- refreshPromise serializes concurrent attempts so only one hits server
- Removed signOut() from getSession/getUser wrappers to prevent cascade
- Module-level invalidTokenDetected shared across all calls

Fixes production auth retry storms ending in 429 rate limits.
