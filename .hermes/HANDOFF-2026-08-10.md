## 3. AKUTT #2: auto-rollback kan aldri virke — JSON.parse-krasj

**Rotårsak (bevist i run 31381929006, steg «Finn forrige versjon og rull tilbake»):**
```
SyntaxError: Unexpected end of JSON input
##[error]Process completed with exit code 1.
```

Workflow-linjen (`.github/workflows/deploy.yml`, ~linje 199):
```bash
PREV_VERSION=$(npx wrangler versions list --json 2>/dev/null | node -e "...JSON.parse...")
```

**Kjeden:** `wrangler versions list --json` returnerer **TOMT** i CI → `JSON.parse('')` krasjer → `exit 1` → **rollback forsøkes aldri**. Og `2>/dev/null` svelger den egentlige wrangler-feilen, så loggen viser bare symptom.

**Viktig diagnostikk (K3 testet lokalt 2026-08-10 ~13:40):**
- `npx wrangler versions list --json` med lokale nøkler (`.env.local`) → **virker fint** (returnerer gyldig JSON, siste versjon #1624).
- Konklusjon: **CI-spesifikt problem** — ikke wrangler-bug. Sannsynlige kandidater:
  1. `CLOUDFLARE_API_TOKEN` i GH secrets mangler rettighet for `versions list` (trenger Workers Scripts: Read; `versions deploy` trenger Edit).
  2. Token i CI er utløpt/rotet etter nøkkelrotasjonen 2026-08-02 (sjekk at GH-secret ble oppdatert da).
  3. `CLOUDFLARE_ACCOUNT_ID` mangler/feil i CI-miljøet.

**Fiks-forslag (i prioritert rekkefølge):**
1. Fjern `2>/dev/null` i workflow-linjen — la den reelle wrangler-feilen inn i loggen.
2. Guard mot tomt svar før `JSON.parse` (`if [ -z "$RAW" ]; then echo "::error::wrangler versions list returnerte tomt"; exit 1; fi`).
3. Verifiser/forny `CLOUDFLARE_API_TOKEN` i GH secrets med Workers: Edit.
4. Test kjeden bevisst (f.eks. midlertidig feilende smoke i staging) for å bevise at rollback faktisk virker — **ikke anta det**.

**Hvorfor kritisk:** Hvis en faktisk ødeleggende deploy når prod mens dette står slik, er det **ingen automatisk sikkerhetsventil**. Prod ble reddet denne gangen kun fordi K3s deploy var god.

**Trello:** 2× «🚨 AUTO-ROLLBACK: innlogget smoke feilet» (🚨 Varsler).
