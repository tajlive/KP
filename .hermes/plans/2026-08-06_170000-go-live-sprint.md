## Fase 1 — Parallell Produksjonsaudit

Fire subagenter undersøker hvert sitt domene. Kun lesing — ingen kodeendringer, ingen deploy.

### Agent A — Trading, Cron og Datakvalitet

**Scope:**

- `sync-prices` cron — auth (`APP_URL` + `CRON_SECRET`), hyppighet, feilhåndtering
- `coin_prices` — dataalder, alarm ved >10 min, guard ved >15 min
- `reconcile` — idempotens, retry, 429, timeout, worker-redeploy
- `autopilot-orchestrator` — pg_cron job 1176, hvert 5. min
- Kill-switch — maksimal eksponering, daglig tapsgrense, manuell nød-pause
- Circuit-breaker — trading/rebalance guard

**Leveranse:** P0/P1/P2-liste, berørte filer, tryggeste fixplan

### Agent B — Auth, API og Sikkerhet

**Scope:**

- Auth-middleware, HttpOnly-cookies, `/api/auth/me`, logout
- `/api/admin/*` — admin-autorisasjon
- `/api/cron/*` — CRON_SECRET-validering
- `/api/webhooks/*` — signaturvalidering
- CSRF, rate limits, RLS, logging av sensitive data
- Health-worker: 522/4xx/5xx må gi feilstatus (ikke `ok`)

**Leveranse:** Prioriterte funn med reproduserbare tester

### Agent C — Mobil UX og Konvertering

**Scope (fire viewports: 375×667, 390×844, 412×915, 768×1024):**

- Forside → registrering/login → onboarding → paper trade → dashboard → Auto Trade → profil → betaling
- Bottom nav, UserMenu/bottom sheet, tabber, modaler, charts, toasts
- Safe-area, scroll-lock, tastatur, kontrast, touch-mål (≥44×44 px), CTA-tilgjengelighet
- `/no/trade?tab=auto` fra mobil og e-postruting
- Radix-menyer: `onSelect` vs `asChild + Link`

**Leveranse:** Repro-steg, screenshots for reelle feil, patchforslag P0/P1/P2

### Agent D — SEO, i18n, Observability og Release

**Scope:**

- Sitemap, robots, canonical, hreflang, OG-bilder, metadata
- Manglende i18n-nøkler for legal, pricing success, pricing cancel
- Staging/produksjonsmonitorering, syntetisk testbruker, varsler
- GitHub Actions: branch protection, E2E, Lighthouse, CodeQL
- Dependabot: klassifiser runtime vs dev/build

**Leveranse:** Go/no-go-sjekkliste, CI/monitoreringsgap
