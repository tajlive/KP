# Auto Trade Implementation Plan

> **For Hermes:** Bruk subagent-driven-development skill for å implementere denne planen task-for-task.

**Goal:** Fullføre auto trade (autopilot) slik at studenter kan aktivere AI-trading med én knapp — trygt, forståelig, og med samme engine for leke/live.

**Architecture:** Eksisterende autopilot-orchestrator (pg_cron 5-min) → decision-engine → strategy execution. Mangler: student-vennlig UI, onboarding, risiko-forklaring, progresjonsmåling.

**Tech Stack:** Next.js 16, Supabase, Kraken/OKX API, React 19, TypeScript.

**Step 1: Lag stop-endpoint**

```typescript
// stop/route.ts
export async function POST(req: NextRequest) {
  const { userId } = await getUser(req);
  
  // Stopp alle aktive sesjoner
  await db.from('trading_sessions')
    .update({ status: 'stopped', stopped_at: new Date() })
    .eq('user_id', userId)
    .eq('status', 'active');
  
  // Logg beslutningen
  await logDecision(userId, 'autopilot_stopped', { reason: 'user_request' });
  
  return NextResponse.json({ stopped: true });
}
```

## Risikoer og åpne spørsmål

| Risiko | Mitigering |
|--------|-----------|
| Student panikk-selger ved første nedgang | Risiko-modal + progresjonsmåling |
| For mange går live for tidlig | Krav: 10 trades, positiv P&L, 1 uke |
| API-nøkkel misbrukt | Kun trade-tilgang, aldri withdrawal |
| Autopilot gjør dårlige trades | Samme engine som leke — testet |

**Åpne spørsmål:**
1. Skal student selge manuelt, eller kun stoppe autopilot?
2. Hva skjer med åpne posisjoner ved stopp? (selges eller holdes?)
3. Skal Pro-tier ha flere strategier enn Student?
