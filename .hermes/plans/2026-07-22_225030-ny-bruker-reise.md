# Ny-bruker-reisen: registrer → logg inn → trade → se sin trading — Implementation Plan

> **For Hermes:** Bruk subagent-driven-development ved utførelse: én fersk subagent per task, med spec-compliance review og code-quality review før neste task.

**Goal:** Gjøre reisen fra ny registrering til første handel og innsyn i egen trading moderne, logisk og mobilførst — bygget på eksisterende komponenter (SpeedOnboarding, AdaptiveDashboard, UnifiedTradeTerminal, FirstTradeReward, OnboardingProgress).

**Architecture:** Én anbefalt hovedretning (Alternativ B+A) med to dokumenterte alternativer. Ingen nye routes utover det som finnes — vi bygger videre på `/register`, `/login`, `/onboarding`, `/dashboard`, `/trade`, `/dashboard/historikk`, `/dashboard/portfolio`. Progressive disclosure, paper-first, én primær CTA per visning.

**Tech Stack:** Next.js 16 App Router, React 19, next-intl (konsoliderte `messages/no.json` + `en.json` — ALDRI split-filer), Supabase (client-side auth via `AuthProvider`/`useAuth()`), framer-motion, Vitest.

## De tre alternativene

### Alternativ A — "Første handel på 60 sekunder" (lineær wizard)

**Konsept:** Etter registrering går brukeren rett inn i en guidet 3-stegs første-handel: (1) Velg coin → (2) Velg beløp i NOK → (3) Bekreft. Ferdig → konfetti + "Se hva som skjedde" → lander på dashboard med første trade synlig.

- **Bygger på:** `SpeedOnboarding.tsx` (allerede en lineær flyt), `TradeExampleCard`, `UnifiedTradeTerminal` sin paper-motor, `FirstTradeReward`.
- **Styrke:** Raskest tid til verdi (TTV). Firi/eToro-følelse. Målbart (funnel: registrert → handel fullført).
- **Svakhet:** Tvangsstyrt — brukere som vil utforske først må avbryte. Krever tydelig "Hopp over"-exit som likevel gir verdi.
- **Endringsomfang:** Middels. Én ny canonical onboarding-flyt, de to andre (`OnboardingFlow`, `InteractiveOnboardingWizard`) saneres.

### Alternativ B — "Velkomst-hub med sjekkliste" (Duolingo/Revolut-stil)

**Konsept:** Etter registrering lander brukeren på dashboard hvor NyBruker-viewet blir en 3-punkts sjekkliste: ☑ Konto opprettet → ☐ Gjør din første handel (lekepenger) → ☐ Se resultatet ditt. Hvert punkt er én tydelig CTA. Punktene hukes av med ekte data (trades i DB), ikke lokal state.

- **Bygger på:** `AdaptiveDashboard` NyBruker-view, `OnboardingProgress`, `SmartActions`, `FirstTradeReward`, `SimplifiedHero`.
- **Styrke:** Ikke-tvungen; brukeren eier tempoet. Dashboard blir "hjem" fra første sekund (porteføljeførst-prinsippet). Lav risiko — ingen ny route.
- **Svakhet:** Svakere "wow"-opplevelse enn A; avhenger av at CTA-ene faktisk leder til god /trade-opplevelse.
- **Endringsomfang:** Lav-middels. Primært dashboard + i18n + analytics-events.

### Alternativ C — "Kontekstuell guide i eksisterende flater" (coachmarks)

**Konsept:** Behold dagens struktur 100 %. Legg til kontekstuelle hint: første gang /trade åpnes → tooltip-sekvens ("Slik kjøper du"), første gang historikk åpnes → hint om lesing av PnL. `MicroLearning.tsx` brukes som motor.

- **Bygger på:** `MicroLearning.tsx`, `AITip`, eksisterende sider uendret.
- **Styrke:** Minst endring. Null ny navigasjon.
- **Svakhet:** Løser ikke "hvor starter jeg"-problemet — bare forklarer flatene. Coachmarks har lav gjennomføringsgrad på mobil.
- **Endringsomfang:** Lav.

### Anbefaling: **B som ramme + A som innhold i punkt 2**

Sjekklisten (B) er rammen fordi den ikke tvinger og gjør dashboard til hjem. Men punkt 2 ("Gjør din første handel") åpner en **forenklet guided handelsflyt inne i `/trade`** (A-mekanikken): en "første gang"-modus i `UnifiedTradeTerminal` med coin-velger → NOK-beløp → bekreft, uten de avanserte tabbene. Etter første fylte handel vises `FirstTradeReward` og punkt 3 låses opp.

Dette respekterer alle låste UX-krav: én CTA per visning, paper-first, progressive disclosure (avansert skjult til etter første handel), samme `/trade`-route for alle.

## Målbilde: reisen steg for steg

1. **Registrer** (`/register`) → etter suksess: redirect til `/dashboard` (ikke `/onboarding`-runddans). Velkomst-toast: "Kontoen din er klar — 100 000 kr lekepenger er satt inn".
2. **Dashboard (NyBruker)** viser `OnboardingChecklist` med 3 punkter; punkt 1 allerede avhuket. Én primær CTA: "Gjør din første handel".
3. **`/trade?first=1`** åpner guided modus: 3 steg (coin → beløp → bekreft). Paper/l live-badge synlig ("Lekepenger"). Ingen auto/AI-tabs før første handel er fullført.
4. **Bekreftelse:** `FirstTradeReward` + "Se handelen din" → scroll/lenke til `RecentTrades` (eller `/dashboard/historikk`).
5. **Punkt 3 hukes av** når brukeren har sett historikken (event `history_viewed` eller enkel tilstedeværelse). Onboarding fullført → `OnboardingCompletion`-feiring → dashboard går til `Onboarded`-view.
6. **Login for returnerende ny bruker** (ikke fullført sjekkliste) → rett til dashboard med sjekklisten intakt ("fortsett der du slapp" er implisitt).

```tsx
"use client";
import { useTranslations } from "next-intl";
import Link from "next/link";
import { Check } from "lucide-react";

interface Props {
  hasAccount: boolean;
  tradeCount: number;
  hasViewedHistory: boolean;
}

export function OnboardingChecklist({ hasAccount, tradeCount, hasViewedHistory }: Props) {
  const t = useTranslations("dashboard.onboardingChecklist");
  const items = [
    { id: "account", done: hasAccount, label: t("accountCreated"), href: null },
    { id: "first-trade", done: tradeCount > 0, label: t("firstTrade"), href: "/trade?first=1" },
    { id: "see-result", done: hasViewedHistory, label: t("seeResult"), href: "/dashboard/historikk" },
  ];
  const allDone = items.every((i) => i.done);
  if (allDone) return <div data-testid="checklist-complete">{t("complete")}</div>;
  return (
    <ul className="space-y-3">
      {items.map((item) => (
        <li key={item.id} data-testid={`check-${item.id}`} data-done={item.done}
            className="flex min-h-[48px] items-center gap-3">
          <span className={item.done ? "text-emerald-400" : "text-zinc-500"}>
            <Check size={20} />
          </span>
          {item.href && !item.done ? (
            <Link href={item.href} className="text-base font-medium underline-offset-4">
              {item.label}
            </Link>
          ) : (
            <span className={item.done ? "text-zinc-400 line-through" : ""}>{item.label}</span>
          )}
        </li>
      ))}
    </ul>
  );
}
```

**Step 1:** Hook som leser `trades`-antall (count head-only query, `user_id` + `mode='paper'`) og `localStorage`-flagg `kp_history_viewed` (settes i Task 5):
```ts
"use client";
import { useEffect, useState } from "react";
import { createClient } from "@/lib/supabase/client";

export function useOnboardingState(userId: string | null) {
  const [tradeCount, setTradeCount] = useState(0);
  const [hasViewedHistory, setHasViewedHistory] = useState(false);
  useEffect(() => {
    setHasViewedHistory(localStorage.getItem("kp_history_viewed") === "1");
    if (!userId) return;
    const supabase = createClient();
    supabase.from("trades").select("id", { count: "exact", head: true })
      .eq("user_id", userId).eq("mode", "paper")
      .then(({ count }) => setTradeCount(count ?? 0));
  }, [userId]);
  return { tradeCount, hasViewedHistory };
}
```
*(Kolonnene `user_id`, `mode` er verifisert mot regenererte typer — ikke bruk `symbol` eller andre gamle navn.)*

## Risikoer, tradeoffs og åpne spørsmål

| Risiko | Mitigering |
|---|---|
| Tre onboarding-flyter i kodebasen — ukjent hvilken som faktisk rendres i prod | Task 1 kartlegger importers FØR noe endres |
| `user_trading_config` finnes ikke i prod (TODO fra skjemaretting) — SpeedOnboarding sin persistens er stille feilende | Ikke bygg ny funksjonalitet på denne tabellen; bruk `user_profiles` + `trades` som sannhet |
| `first=1`-modus kan fragmentere /trade | Query-param opt-in; eksisterende brukere og direkte `/trade` er uendret |
| `analytics_events` finnes ikke — funnel-måling kan være umulig uten DB-endring | Task 7 verifiserer faktisk skrivevei først; ellers kun localStorage-dedup og UI-state |
| i18n: nye nøkler må i konsoliderte filer | Eksplisitt steg i hver task; `i18n:validate` er gate |

**Åpne spørsmål til Tom (ikke blokkerende):**
1. Skal "Hopp over"-exit i guided flyt føre til vanlig terminal eller til dashboard? *(Plan antar: vanlig terminal — brukeren har allerede vist handelsintensjon.)*
2. Minimumsbeløp første handel: 50 kr? *(Justerbart i FirstTradeFlow-konstant.)*
3. Skal sjekklisten forsvinne helt etter fullføring, eller kollapse til en liten "fullført"-badge?

**Ikke-mål (YAGNI):** Ingen endring i live-trading-flyt, ingen nye routes, ingen redesign av portefølje/resultater, ingen endring i 4-bunnfaner-IA, ingen copy-trading/JokerTrade i ny-bruker-reisen.
