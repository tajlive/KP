# Deploy-strategi & Optimalisering for Klarpakke

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Etablere en rask, pålitelig og automatisert deploy-pipeline for Klarpakke — med optimalisert Supabase, Cloudflare, GitHub Actions og lokal utvikling.

**Architecture:** Endre fra treg lokal build (10 min) til CI-basert deploy på GitHub Actions. Bruk Workers Builds for incremental deploy, fallback workflow for full rebuild. Optimaliser secrets management og hastighet.

**Tech Stack:** Cloudflare Workers, Wrangler, GitHub Actions, Supabase, OpenNext.js

---

## 🔍 Nåværende smertepunkter

| Problem | Årsak | Konsekvens |
|---------|-------|------------|
| **Lokal build 10+ min** | M1 Mac, 1457 Next.js filer, full OpenNext build | Kan ikke iterate raskt |
| **Workers Builds treg** | Tar 5-15 min å starte | Venter på deploy |
| **CI fallback feiler** | Smoke test false positive | Deploy må trigges manuelt |
| **`cfg:build` må gjøres før `wrangler deploy`** | .open-next/ cache blir utdatert | Gammel kode deployes |
| **Anon key hardcodet i kode** | Supabase table/view utenfor autogenerated types | Sikkerhetsrisiko + feil ved key-rotasjon |
| **I18n endringer trenger rebuild** | Locales er bundled i JS | Kan ikke hot-fix tekster |
| **Ingen deploy-sjekkliste** | Manuelle steg glemmes | Ufullstendig deploy |

---

## ✅ Mål-tilstand

| Scenario | Før | Etter |
|----------|:---:|:-----:|
| Hotfix (1 linje) | 10 min build + deploy | 2 min via CI |
| Stor feature | 10 min build + deploy | 10 min (samme) |
| I18n fix | 10 min build | 30 sek (ingen rebuild) |
| Secrets rotasjon | 20 min + deploy | 2 min via Supabase + GH |
| Smoke test false alarm | Blokkerer deploy | Ignoreres ved worker crash |

### Task 1: Fiks CI fallback smoke test

**Objective:** Smoke test skal kun sjekke HTTP 200, ikke "Feilkode:" i body (false positive).

**Files:**

**Step 1: Erstatt grep-sjekk**

```yaml
# FØR (false positive — Feilkode: matcher i18n templates)
- run: |
    for url in "..."; do
      curl -s "$url" | grep -q "Feilkode:" && exit 1
    done

# ETTER (kun HTTP status + sjekk på faktisk Worker crash)
- run: |
    for url in "/no" "/no/login" "/no/register" "/api/health"; do
      status=$(curl -s -o /dev/null -w "%{http_code}" "https://www.klarpakke.no$url")
      if [ "$status" != "200" ] && [ "$status" != "307" ]; then
        echo "❌ $url → $status"
        exit 1
      fi
      echo "✅ $url → $status"
    done
```

### Task 3: Bytt til CI-basert deploy som default

**Objective:** All deploy går via GitHub Actions CI, ikke lokal `wrangler deploy`. CI bygger fra scratch i et rent miljø — ingen cache-problemer.

**Files:**
- Create: `.github/workflows/deploy-production.yml`
- Modify: `.github/workflows/deploy-cloudflare-workers-fallback.yml`

**Step 1: Nytt deployment workflow**

```yaml
name: Deploy to Production
on:
  push:
    branches: [main]
    paths-ignore:
      - '*.md'
      - 'docs/**'
      - '.gitignore'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      
      - name: Cache node_modules
        uses: actions/cache@v4
        with:
          path: node_modules
          key: npm-${{ hashFiles('package-lock.json') }}
          
      - name: Install
        run: npm ci
        
      - name: Build
        run: npm run cf:build
        env:
          NEXT_PUBLIC_SUPABASE_URL: ${{ secrets.NEXT_PUBLIC_SUPABASE_URL }}
          NEXT_PUBLIC_SUPABASE_ANON_KEY: ${{ secrets.NEXT_PUBLIC_SUPABASE_ANON_KEY }}
          NEXT_PUBLIC_APP_URL: ${{ vars.NEXT_PUBLIC_APP_URL }}
          
      - name: Deploy
        run: npx wrangler deploy --minify --var APP_VERSION:$(git rev-parse --short HEAD)
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          
      - name: Verify
        run: |
          sleep 10
          curl -sf "$BASE/api/leaderboard?period=weekly" | python3 -c "...
```

**Step 2: Deaktiver Workers Builds (unødvendig)**

Settings → Workers Builds → Disable automatic deployments

```bash
#!/bin/bash
# scripts/sync-secrets.sh — push .env.local → GitHub secrets
while IFS='=' read -r key val; do
  gh secret set "$key" --body "$val" --repo tajlive/KP
done < <(grep -E "^[A-Z_]+=" .env.local | grep -v "^#" | grep -v "POSTGRES\|STRIPE\|VIPPS\|RESEND\|BINANCE\|CRON_SECRET")
```

**Objective:** Dokumenter gangetid for hver deploy-metode. Bruk rett metode basert på endringstype.

**Files:**
- Create: `docs/ops/DEPLOY-DECISION.md`

**Step 1: Decision tree**

```markdown
# docs/ops/DEPLOY-DECISION.md

## Hvilken deploy-metode?

### 🔵 Jeg endrer: Tekst/i18n (messages/*.json)
**Metode:** Push til main → Workers Builds (15 min)
**Alternativ:** `npm run cf:build` + `wrangler deploy` (10 min)

### 🟢 Jeg endrer: Kode (src/*.ts, src/*.tsx)
**Metode:** Push til main → GH Actions (10 min)
**Kommentar:** CI bygger fra scratch, rent miljø

### 🟡 Jeg endrer: Supabase (migrations/*.sql)
**Metode:** `supabase db push` direkte (30 sek)
**Viktig:** Krever POSTGRES_URL_NON_POOLING i .env.local

### 🔴 Jeg endrer: Edge Functions (supabase/functions/*)
**Metode:** `supabase functions deploy` (30 sek)
**Uten rebuild:** Ingen Worker-deploy nødvendig for edge functions

### ⚡ Hotfix (1 linje, kritisk)
**Metode:** 
1. Patch direkte på server (!)
2. `rm -rf .open-next && npm run cf:build && npx wrangler deploy --minify`
3. Push til main (for versjonskontroll)

## Cache-håndtering

| Handling | .open-next/ status |
|----------|-------------------|
| Push til main (GH Actions) | Bygges fra scratch |
| Lokal `wrangler deploy` | Bruker eksisterende cache |
| `rm -rf .open-next` + build | Frisk cache |
| Kun i18n endring | Trenger rebuild |
```

  run: |
    echo "DEPLOY_START=$(date +%s)" >> $GITHUB_ENV
    
- name: Report timing
  if: always()
  run: |
    END=$(date +%s)
    DURATION=$((END - DEPLOY_START))
