# Klarpakke 100% — Media, visuelt innhold og polering

> **For Hermes:** Plan-mode leveranse. Ikke eksekver før Tom velger scope.
> Hver oppgave er uavhengig og kan kjøres isolert.

**Goal:** Ta Klarpakke fra funksjonelt komplett til visuelt/innholdsmessig komplett — bilder, video, PWA-assets og polering som gjør produktet troverdig for nye brukere.

---

## Del 0: Konkurrentanalyse — hva lederne gjør (research 2026-07-23)

### Finelo (nærmeste konkurrent — norsk læringsplattform for trading)
- **Kjernemekanikk:** challenge-basert læring ("28-dagers utfordringer"), 100+ mini-leksjoner, quiz, risikofri simulering — nøyaktig Klarpakkes paper-trading-posisjon
- **AI-vinkling:** "AI-assisted learning, not automated trading" + AI-agenter som demonstrerer strategier på reelle data
- **Social proof-fronting:** utmerkelser (#1 Newsweek/Statista), testimonials, "Millions learn with Finelo"
- **Landing-mønster:** live tickers, ren kort-layout, selvtillits-copy ("Start Trading. Grow Skills. Build Confidence.")
- **Konklusjon for oss:** Klarpakke har bedre teknologi (ekte auto-trading, ekte engine) men svakere *innpakking*: få leksjoner, ingen challenge-narrativ, ingen social proof, ingen visuell story.

### Revolut / Robinhood / Trade Republic (visuell standard)
- **Revolut:** dristige gradients, 3D-enhetsmockups med svevende UI-kort, animerte tall, mørk premium-estetikk. App Store-screenshots = enhetsramme + ÉN fordel per skjerm.
- **Robinhood:** minimalisme, én CTA, motion-first landing (animerte grafer), gamifisering (konfetti — vi har allerede FirstTradeReward!), eget illustrasjonssystem.
- **Trade Republic:** flat, ryddig, "formuesbygging"-narrativ, ekte produktbilder i enhetsrammer.
- **Felles:** produktbildet ER helten. Ingen leder bruker generiske stock-bilder av "glade mennesker som ser på telefon".

### Hva vi kopierer vs. dropper
| Kopier | Dropp |
|---|---|
| Enhetsramme + én fordel per skjerm (App Store/PWA) | Stock-foto av mennesker |
| Levende hero (ambient loop) | Tunge autoplay-videoer med lyd |
| Challenge-narrativ (28-dager → vår onboarding) | Generisk AI-kunst uten produktkontekst |
| Social proof-seksjon (testimonials/tall) | Fake anmeldelser — kun ekte data |
| Ett konsistent illustrasjonssystem | Mer enn 2–3 stiler totalt |

## Del 0B: Hva er faktisk mulig med vårt verktøy (fakta, ikke hype)

**K3 er en språkmodell — den genererer IKKE bilder/video selv.** Rollene:

| Verktøy | Kan | Kan ikke |
|---|---|---|
| **K3 (Kimi)** | Art direction: prompts, storyboard, copy, i18n-tekst, kode som bygger grafikk (SVG, CSS-art, dynamiske OG-bilder), A/B-varianter, analyse | Piksler/video direkte |
| **`video_generate` (xAI grok-imagine)** | Tekst→video, bilde→video (animer et stillbilde), opptil 7 referansebilder, 1–15s, 480p/720p, 9:16+16:9, chaining (extend) | Lyd av høy kvalitet, >15s, presis UI-tekst i video |
| **ComfyUI (skill)** | Full bildepipeline: Flux/SDXL, stilkonsistens via ControlNet/LoRA, oppskalering, batch | Krever GPU-oppsett første gang |
| **`text_to_speech`** | Norsk voiceover til videoer (edge/openai-stemmer) | Sang/emosjonell stemmelek |
| **K3 + kode** | Programmatisk grafikk: SVG-illustrasjoner, animerte grafer (framer-motion finnes allerede), dynamiske OG-bilder via `next/og` (ImageResponse) | — |

**Det NYESTE og mest moderne man kan gjøre akkurat nå (2026):**
1. **"Living hero"** — generer ETT perfekt stillbilde (Flux, brand-palett) → animer med bilde→video → 6–8s sømløs ambient loop. Dette er 2026-standarden (Linear, Arc, Raycast gjør varianten av dette).
2. **Chainede produkt-fortellinger** — 3 klipp på 5s kjeded via `video_generate`-chaining: registrer → første handel → resultat, med AI-voiceover fra `text_to_speech` og HTML-tekstoverlay (i18n-sikkert).
3. **Referansestyrt stilkonsistens** — generer alle illustrasjoner med samme referansebilde (opptil 7) → ett visuelt system, ikke tilfeldig AI-kunst.
4. **Dynamiske OG-bilder** — `next/og` ImageResponse: hvert delings-URL (resultat, leaderboard, strategi) får autogenerert bilde med EKTE brukerdata. Gratis, kode, ingen AI-bildekostnad — og mer troverdig enn genererte bilder.
5. **AI-genererte device-scener** — livsstils-/3D-scene generert, ekte UI-screenshot compositert inn i enhetsramme (best av begge: polish + autentisitet).

**Senior-arkitektens advarsel:** Bruk AI-generert media til *ambient/brand-laget* (hero, bakgrunner, illustrasjoner). Bruk EKTE produkt til *produktlaget* (onboarding-video, App Store, feature-visning). Konverteringsdata er entydig: ekte UI slår syntetisk. En bruker som oppdager at "produktvideoen" var AI-generert mister tillit — dødelig for en finans-tjeneste.

## Del 1: Media-produksjon (revidert med konkurranse-innsikt)

### Task 1: PWA install-screenshots (Revolut-mønsteret)
- 3 mobil-skjermer fra prod (dashboard/checklist, guided trade, portefølje)
- Enhetsramme + ÉN fordel-overskrift per skjerm (Revolut-stil): "Lær trading uten risiko" / "Din første handel på 30 sekunder" / "Se resultatene vokse"
- `public/screenshots/*.png` + `manifest.json screenshots[]`
- **Verifisering:** Chrome DevTools → Application → Manifest uten advarsler

### Task 2: "Living hero" på landing (det moderne trekket)
1. Generer hero-stillbilde: mørk fintech-scene, Klarpakke-palett (cyan/amber på #0f1117), abstrakt chart-estetikk — Flux via ComfyUI, 1920×1080
2. Animer via `video_generate` image-to-video: subtil bevegelse (stigende lyskurve, partikler), 6s, 720p, 16:9
3. Loop-klipp: første/siste frame matches (eller revers-pingpong i kode)
4. `public/video/hero-loop.mp4` (<2 MB, ellers bitrate ned) + poster-frame WebP
5. K3: hero-seksjon med `<video muted autoplay loop playsInline poster>` + `prefers-reduced-motion` → statisk bilde
- **Fallback hvis generering skuffer:** CSS/canvas-animert equity-kurve (framer-motion) — allerede stack-native, 0 KB video

### Task 3: Illustrasjonssystem (referansestyrt, 6 stk)
- Generer 1 "stil-anker" (flat, mørk, cyan/amber, geometrisk) → bruk som referansebilde for resten
- 6 illustrasjoner: empty-portfolio, empty-history, empty-leaderboard, empty-results, kurs-crypto, kurs-risiko
- WebP 400×400 <40KB → `public/illustrations/`
- K3: `src/shared/ui/EmptyState.tsx` + utskifting på 4 verifiserte steder
- Test: `src/shared/ui/__tests__/EmptyState.test.tsx`

### Task 4: Onboarding-produktvideo (Finelo-killer)
- **EKTE screen-recording** av golden path (ikke AI): registrer → guided first trade → +200 KLT reward → historikk
- 9:16, 20–30s, `screencapture`/QuickTime på mobil-viewport
- AI-voiceover (text_to_speech, norsk): "Fra konto til første handel på under ett minutt"
- HTML-tekstoverlay for i18n, poster-frame, muted-autoplay variant for landing
- `public/video/onboarding-9x16.mp4` + kobling til `src/features/course/VideoHero.tsx`

### Task 5: Dynamiske OG-bilder (kode, ikke AI — høyeste ROI)
- `src/app/api/og/route.tsx` med `ImageResponse` fra `next/og`
- Varianter: default, resultat-deling (P&L + win-rate), leaderboard-rang
- Brand-maler med tokens fra `src/lib/design/tokens`
- Erstatter/oppgraderer statiske `public/og-image.png`
- Test: snapshot av SVG-output + curl-verifisering av `og:image`-meta

### Task 6: Challenge-narrativ + social proof (Finelo-kopiering, innhold)
- "Kom-i-gang-uken": pakk eksisterende checklist + FirstTradeFlow inn i et 7-dagers challenge-narrativ (kun copy/framing — mekanikken finnes!)
- Landing: social proof-seksjon — KUN ekte tall (antall paper-trades kjørt, leksjoner fullført) via dynamisk OG-telling; ingen fabrikkerte testimonials
- Rå i18n-nøkkel `trading.paperTrading.viewTrades` fikses i samme slengen

### Task 7: Leksjonsinnhold med AI-illustrasjoner (krever scope-beslutning)
- 5 kjernemoduler, hver med 1 generert diagram (stil-ankeret fra Task 3) + quiz
- K3 skriver copy (norsk, enkelt språk — Finelo-nivå), diagrammer fra stilanker

## Risikoer / tradeoffs
- **AI-video i produktkontekst** → tillitstap. Mitigert: kun ambient/bruk aldri som "produktbevis".
- **Ytelse:** hero-video kan koste LCP. Budsjett: <2 MB, poster, lazy under fold. Mål Lighthouse etter.
- **ComfyUI-oppsett** kan ta tid første gang — fallback: xAI bildegen eller ren kode-SVG.
- **Stil-drift:** uten stil-anker blir AI-bilder inkonsistente. Derfor Task 3 før Task 5/7.
